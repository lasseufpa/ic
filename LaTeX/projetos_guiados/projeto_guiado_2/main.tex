\section{Introdução e objetivo}
Este projeto formaliza o desenvolvimento de um sistema de visão computacional para a detecção e localização de açaizeiros utilizando detecção de objetos com YOLO11. O objetivo fundamental é construir um modelo baseado em YOLO11 capaz de detectar e localizar açaizeiros em imagens aéreas ou de campo por meio do uso de conjuntos de dados anotados e técnicas de aprendizado profundo. Neste projeto, os estudantes criarão um conjunto de dados anotado de alta qualidade, desenhando caixas delimitadoras (bounding boxes) ao redor dos açaizeiros visíveis utilizando o Roboflow. O conjunto de dados anotado será posteriormente utilizado para treinar e avaliar um modelo de detecção de objetos YOLO11 utilizando Python. As equipes irão treinar e testar seus modelos para determinar qual equipe alcança o melhor desempenho de detecção de objetos no conjunto de dados de teste.

\end{itemize}


\section{O conjunto de dados: estrutura e atributos}
O conjunto de dados consiste em imagens aéreas ou de campo contendo açaizeiros visíveis. Cada imagem representa uma instância para anotação, enquanto cada anotação corresponde a um açaizeiro detectado. As anotações seguirão o formato de detecção de objetos do YOLO11: $[\text{classe}, x, y, w]$, em que $x$ e $y$ representam as coordenadas dos eixos $x$ e $y$ normalizadas do centro da \textit{bounding box}, respectivamente. Ademais, $w$ e $h$ representam a largura e a altura do centro da \textit{bounding box}. Todas as coordenadas são normalizadas entre 0 e 1.

Para este projeto, apenas açaizeiros devem ser anotados. O processo de anotação deve utilizar caixas delimitadoras retangulares (bounding boxes), e todas as anotações devem usar o rótulo de classe consistente \texttt{acai}. As caixas delimitadoras devem envolver de forma precisa a copa ou a parte visível de cada açaizeiro, minimizando a inclusão desnecessária do fundo da imagem. Cada imagem pode conter um único açaizeiro, múltiplos açaizeiros, árvores parcialmente visíveis ou árvores sobrepostas. Nos casos em que múltiplas árvores aparecem na mesma imagem, cada árvore deve ser anotada separadamente. Árvores parcialmente visíveis, mas identificáveis, também devem ser anotadas, desde que possam ser reconhecidas com confiança como açaizeiros. As anotações serão posteriormente exportadas no formato YOLO11 para o treinamento do modelo de detecção de objetos.

\section{Preparação e requisitos na entrega}
Considerando o conjunto de dados anotado e o fluxo de trabalho de detecção de objetos com YOLOv11, cada equipe deverá projetar e treinar seu próprio modelo YOLOv11 utilizando o conjunto de dados anotado, de modo que cada equipe ficará responsável por anotar mais de 150 imagens (há uma variação dependendo do conjunto de dados atribuído a cada equipe). A divisão do conjunto de dados seguirá a ordem dos registros das equipes no documento fornecido. Os conjuntos de dados para cada equipe podem ser consultados por esse \href{https://nextcloud.lasseufpa.org/s/xdHLM7wJiBi65Bt?path=%2F}{link}. Além disso, cada equipe deverá entregar: 
\begin{itemize}
\item Um notebook Jupyter em formato \texttt{.ipynb};
\item Um conjunto de dados com imagens anotadas;
    \item Funções para avaliar o desempenho do modelo treinado a partir das imagens anotadas.
\end{itemize}

O notebook deve documentar todas as etapas do desenvolvimento, desde a anotação das imagens até a análise final do desempenho da detecção de objetos. Seguindo esta orientação inicial, as equipes deverão entregar os seguintes resultados:
\begin{itemize}
    \item \textbf{RQ1}: As imagens atribuídas devem ser totalmente anotadas utilizando o Roboflow. O processo de anotação deve identificar todos os açaizeiros visíveis, utilizar caixas delimitadoras (bounding boxes) precisas e manter a consistência na qualidade das anotações.
    \item \textbf{RQ2}: A equipe deverá treinar um modelo de detecção de objetos YOLOv11 utilizando Python. O notebook deve incluir o carregamento do conjunto de dados, o treinamento do YOLOv11, os testes de predição e as métricas de avaliação.
    \item \textbf{RQ3}: A equipe deverá fornecer métricas de desempenho, incluindo precisão, recall, mAP@50 e mAP@50-95, \textcolor{red}{levando em consideração que o conjunto de dados de teste deve ser construído a partir de 20\% do conjunto de dados original fornecido}.
    \item \textbf{RQ4}: A equipe deverá fornecer exemplos (pelo menos um) de predições mostrando os açaizeiros detectados, as caixas delimitadoras (bounding boxes) e os níveis de confiança (confidence scores).
\end{itemize}

\section{Regras}
Para este projeto, haverá dois tipos de avaliação:

\begin{itemize}
    \item Uma avaliação deve levar em consideração o conhecimento e o domínio da equipe na apresentação da solução proposta, tanto durante a apresentação quanto na avaliação do notebook Jupyter entregue. Os pontos para essa avaliação serão de \textbf{0 a 10}.
    \item Uma segunda avaliação, \textbf{valendo pontuação extra}, levará em conta a competição do melhor modelo obtido entre as equipes.
\end{itemize}

\subsection{Regras para a avaliação sobre o domínio do assunto}

    \begin{itemize}
    \item O entregável deverá ser um notebook Jupyter no formato \texttt{.ipynb}, contendo a solução proposta pela equipe e um arquivo em formato \texttt{.zip} contendo apenas \textbf{20} imagens e suas respectivas anotações.
    \item Cada equipe será responsável por desenvolver um notebook Jupyter, detalhando todas as etapas de desenvolvimento, desde a manipulação dos dados até a análise final de desempenho.
    \item Cada equipe deve utilizar o mesmo modelo de YOLO. Nesse caso, a versão 11 (YOLOv11).
    \item A entrega deverá ser feita exclusivamente pelo SIGAA. O prazo para entrega é \textcolor{red}{\textbf{01/06/2026} até às \textbf{23h59}}.
    \end{itemize}


\subsection{Regras para a competição}
Após a entrega de todos os notebooks Jupyter, será feito um ranqueamento das melhores soluções, levando em consideração a métrica de mAP@50 no conjunto de teste. Nesse sentido, algumas regras devem ser observadas:

\begin{itemize}
    \item Não é permitido o uso de modelos de YOLO além da versão 11 mencionada. Havendo uso, a equipe ficará com zero pontos na tabela de classificação da competição.
    \item Se duas ou mais equipes atingirem o mesmo valor de acurácia no conjunto de teste, o critério de desempate será a data/hora de envio no SIGAA. A equipe que realizar o envio mais rápido ganhará.
    \item Os pontos obtidos nesta competição seguirão para os próximos projetos guiados.
\end{itemize}
